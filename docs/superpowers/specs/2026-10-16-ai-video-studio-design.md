## 1. 产品目标

“爱视频”首先是一套个人及内部团队使用的 AI 影视生产平台，后续演进为允许外部用户注册、购买套餐并按生成量计费的多租户 SaaS。

第一阶段优先打通两条真实生产链：

1. 文字生成图片。
2. 短故事生成带镜头、旁白、对白、字幕和背景音乐的 30 秒至 3 分钟短视频。

紧随其后的阶段支持小说及长文本拆解，将内容组织为作品、分集、场景和镜头，并批量生成可继续编辑的素材。长篇流程必须复用第一阶段的图片、图生视频、音频、字幕和合成能力，不能形成第二套割裂的生成系统。

第一版在线编辑采用“镜头编排台 + 简化时间线”，支持镜头排序、裁切、转场、音量、字幕调整、素材替换和重新合成，不实现 Premiere 或剪映级多轨编辑器，但保留以后接入多轨编辑内核的接口。

## 2. 用户、权限与 SaaS 演进

内部团队版本从第一版启用账号和权限，提供四种角色：

- 所有者：管理组织、成员、系统配置和全部项目。
- 管理员：管理成员、工作流配置和项目，但不能转移所有权。
- 创作者：创建项目、提交生成任务、编辑分镜和导出作品。
- 审阅者：查看项目、预览素材并提交审阅意见，不能消耗生成资源。

权限同时作用于组织和项目。所有生成任务记录租户、创建人、项目、工作流版本、GPU 占用时长、存储量和其他资源消耗。内部版本不启用计费，但数据模型从开始保留 `tenant_id`、配额和用量流水，后期增加公开注册、套餐、支付和运营后台时不重写生成核心。

## 3. 首个里程碑

首个里程碑仅聚焦可真实验证的纵向切片：

- 用户登录后进入中文“快速生成台”。
- 输入提示词并选择生成图片或生成视频。
- 图片直接调用已验证的 ComfyUI 文生图工作流。
- 视频采用“文字规划 -> 生成首帧 -> 首帧图生视频”的已验证链路。
- 页面持续显示排队、规划、生成、转存和转码进度。
- 生成结果写入平台素材库，可在线预览、下载、查看来源和再次生成。
- 页面刷新、浏览器关闭或 Worker 重启不会丢失任务。

快速生成台采用左右分栏：左侧是提示词、生成类型、画幅、种子和少量高级参数；右侧是任务进度、生成预览、失败原因及下载和再次生成操作；下方展示最近生成记录。

第一版只开放经过验证的受限参数，不向普通用户暴露模型文件名、节点名、采样器和底层工作流 JSON。

## 4. 总体架构

系统采用“模块化单体业务层 + 独立异步 Worker”，通过 Docker Compose 部署。

### 4.1 组件

- `web`：Next.js 中文 Web 应用，提供登录、快速生成台、项目、任务、素材库和管理页面。
- `api`：FastAPI 服务，负责认证、授权、参数校验、任务创建、历史查询和受控素材访问。
- `worker`：执行长任务，持有远程 AI 服务访问权限并调用 Ollama/ComfyUI。
- `media-worker`：使用 FFmpeg 生成缩略图、网页预览、字幕和最终视频合成。
- `postgres`：持久化用户、组织、项目、任务、步骤、工作流、素材、镜头和用量流水。
- `redis`：承载任务队列、短期进度事件和全局 GPU 租约；最终任务状态始终以 PostgreSQL 为准。
- `object-storage`：开发环境使用 MinIO，生产环境可切换为 S3 兼容存储。

Web 浏览器只访问平台 Web/API，不连接 GPU 服务器，不接触 Cloudflare Access 凭据，也不使用 ComfyUI 临时输出地址作为正式素材地址。

### 4.2 适配器边界

- `OllamaAdapter`：模型发现、结构化文本生成和模型卸载确认。
- `ComfyUIAdapter`：上传输入图、提交白名单工作流、追踪 `prompt_id`、取消、查询 history 和下载输出。
- `StorageAdapter`：屏蔽 MinIO 与未来云对象存储差异。
- `WorkflowRegistry`：管理已审核工作流模板、版本、可编辑参数和硬限制。
- `ModelRouter`：根据业务步骤、质量级别、资源成本和健康状态选择 Ollama 模型，并记录实际使用模型与回退原因。
- `ComputeNodeRegistry`：管理远端节点、能力标签、显存等级、启停状态和健康状态；业务代码不得写死服务器域名。
- `SpeechProvider`：通过服务端受控接口调用 Qwen3-TTS，返回最终音频及可强制对齐的时间信息；没有可调用接口时必须显示“未配置”并阻止合成。
- `AlignmentProvider`：以最终音频为权威输入生成句级、词级时间戳，不允许用预设字幕时间反向约束语音。
- `LipSyncProvider`：只处理已锁定 speaker 的说话镜头并生成派生视频资产，失败时不破坏原视频。
- `ContinuityEvaluator`：对人物身份、场景、运动方向、曝光、色温和环境音连续性进行逐镜头评分。

这些适配器必须具有稳定的领域接口，远端 URL、模型和工作流变化不得扩散到页面与核心业务逻辑。

## 6. GPU 调度与任务状态机

远程服务器只有一张 RTX 3060 12GB，Ollama 与 ComfyUI 共享 GPU，且远端没有统一调度器。平台必须实现单 GPU 全局租约，第一版重型 GPU Worker 并发固定为 `1`。

推荐执行顺序：

1. 获取重型任务调度资格。
2. 使用 Ollama 完成提示词、故事或分镜规划，请求设置 `keep_alive: "0s"`。
3. 确认 Ollama 模型已经卸载。
4. 执行 ComfyUI 图片或视频生成。
5. 下载结果并转存平台对象存储。
6. 释放全局 GPU 租约。

音乐、音效、TTS、口型同步与图片/视频共享同一张 GPU，全部进入同一全局串行调度。任何音频类任务提交前必须确认 ComfyUI `queue_running` 和 `queue_pending` 均为空，随后调用 `POST /free`，任务结束或失败后再次以 `{"unload_models": true, "free_memory": true}` 调用 `/free`。队列非空时任务保持等待，不得自动并发重试或绕过平台租约直接提交。

上传、数据库访问、对象存储转存、FFmpeg 转码和普通页面请求不占用 GPU 租约，可以独立并发。

统一任务状态包括：

- 草稿
- 已排队
- 文本规划中
- 生成图片中
- 生成视频中
- 生成语音中
- 音频对齐中
- 口型同步中
- 连续性质检中
- 转场与混音中
- 转存中
- 转码中
- 已完成
- 取消中
- 已取消
- 失败
- 需人工处理

远端生成步骤还必须保存 `validating`、`remote_submitted`、`running`、`downloading`、`quality_check` 和 `persisted` 等细粒度阶段，用于可靠恢复和单镜头质量审查。业务层中文状态可以聚合显示这些执行阶段。

每个任务继续拆为可恢复步骤。步骤记录开始和结束时间、尝试次数、远端任务 ID、输入版本、输出素材及脱敏错误。GenerationTask 必须持久化 `prompt_id`、能力类型、脱敏参数摘要、提交/完成时间和失败原因；输出文件继续作为 Asset 保存并建立父子素材关系。Cloudflare Access 401/403 的业务文案固定为“服务认证失败”。

GenerationStep 还必须保存版本化恢复点与 `qa_status`，用于从已完成的关键图、语音、字幕、镜头运动、混音或渲染阶段继续执行。恢复点只保存对象存储引用、输入摘要、模型/工作流/策略版本和远端任务标识，不保存 Secret 或任意远端路径。

长文本生产至少使用以下可恢复步骤名：`source_preprocessed`、`production_design_locked`、`keyframes_generated`、`narration_generated`、`alignment_completed`、`timeline_built`、`subtitles_built`、`audio_mixed`、`render_packaged`、`qa_completed`。每一步的 `qa_status` 使用 `pending|passed|failed|not_applicable|passed_with_limitations`，页面和恢复逻辑必须使用同一枚举。

## 7. 图片生成数据流

1. API 校验用户权限、提示词长度、尺寸、批量数和配额。
2. 创建数据库任务和幂等键，然后提交队列。
3. Worker 获得 GPU 租约，从 `WorkflowRegistry` 获取白名单模板并注入受限参数。
4. 调用 ComfyUI `POST /prompt`，收到结果后立即持久化 `prompt_id`。
5. 优先通过 `/ws?clientId=...` 获取实时进度，断线时回退到 `/history/{prompt_id}` 轮询；`/history/{prompt_id}` 是最终结果的权威来源。
6. 完成后依据 history 返回的文件信息调用 `/view` 下载输出。
7. 校验文件类型、大小和摘要后转存对象存储。
8. 创建素材、缩略图和来源记录，向网页发布完成事件。

## 8. 视频生成数据流

1. Ollama 将输入整理为首帧画面提示和动作提示。
2. 使用 `keep_alive: "0s"` 并确认模型卸载。
3. 执行文生图工作流，生成并持久化首帧素材。
4. 将首帧上传至 ComfyUI。
5. 注入动作提示及受限视频参数，执行 Wan 图生视频工作流。
6. 下载 MP4 和轻量预览输出，校验并转存对象存储。
7. 建立“用户文字 -> 首帧 -> 视频”的素材来源关系。
8. 生成网页可播放预览，并提供下载、复制参数和重新生成功能。

图生视频输入文件名必须由后端生成，并包含租户、项目、镜头和随机后缀；禁止跨租户可碰撞名称，也不得依赖 `overwrite=true`。当前已验证单镜头参数为 512×512、81 帧、16 FPS、20 steps，约 5.06 秒；这些值由版本化模板策略管理，普通用户不能突破服务器硬上限。生产只保留必要的 MP4 输出，轻量预览由媒体 Worker 异步制作，避免 ComfyUI 同步 WebP 节点增加 GPU 后处理开销。

作品、镜头和 Render 必须显式记录 `media_generation_mode`：`generated_keyframe_motion` 表示生成关键图后通过推拉、平移、裁切等时间线运动形成镜头；`full_generated_video` 表示由视频生成模型直接产生连续帧。关键图运动成片不得在 API、Web 文案或验收中冒充完整生成式视频。每个关键图运动镜头保存 `source_image_id`，并与 `shot_id`、`subtitle_cue_id`、Character/Scene Bible 版本、恢复点和 QA 状态关联。

## 9. 短故事与长篇生产

内容层级固定为：

`作品 -> 版本 -> 分集 -> 场景 -> 镜头 -> 生成任务 -> 素材版本`

### 9.1 短故事

Ollama 输出结构化剧本，包括角色、场景、镜头、旁白、对白、动作、景别、机位、时长和视觉提示词。用户在消耗 GPU 前审阅分镜。系统先创建角色卡、场景卡和风格卡并生成关键帧，用户确认关键帧后再生成镜头视频，减少昂贵的视频返工。

完成镜头后，系统通过 Qwen3-TTS Provider 生成最终旁白/对白，通过 ACE-Step 生成配乐、Stable Audio Open 生成环境音或音效，再进入对齐、口型、字幕、时间线和 FFmpeg 成片。Provider 未配置或接口不可调用时必须显示“未配置”并阻止对应阶段，不伪装为已实现功能。

当前 Wan 1.3B 工作流不得一次承担连续 30 秒生成。标准 30 秒短片采用 6 个约 5 秒镜头：先建立角色、服装、场景、光线和色彩组成的结构化“视觉圣经”，再生成六张不同角度的关键帧；每张关键帧审核通过后依次执行图生视频。单个失败镜头可以独立重试或替换，不影响其他合格镜头。

每个视频镜头至少抽取首帧、中帧和末帧进行质量检查，复杂动作可每秒抽帧。检查项包括人脸漂移、手脚畸形、服装跳变、闪烁、肢体融合、镜头突变和静止假视频。合成前由 FFmpeg 统一分辨率、FPS、SAR、色彩空间和 `yuv420p`，使用短交叉溶解或硬切；最终通过 ffprobe 校验时长、帧数、帧率、分辨率、像素格式和可解码性。

### 9.2 音频、字幕与口型权威时间轴

生产顺序固定为：文本拆句 → 分配 `speaker_id`/`shot_id` → 生成最终语音 → 强制对齐并取得词级时间戳 → 生成字幕 → 生成或修订人物视频 → 口型同步。最终旁白/对白音频是唯一时间轴权威来源，预设镜头或字幕时间只能作为生成目标，不能覆盖实际发音时间。

每条对白和派生结果必须可追溯到 `dialogue_id`、`speaker_id`、`shot_id`、`audio_asset_id`、`subtitle_cue_id`、句级 `start_ms/end_ms`、词级时间戳、对齐模型版本和 `lip_sync_status`。字幕文本必须与实际发音逐字核对；可以为自然语速调整断句，但不能漏字、跨镜头提前或滞后。字幕起止与对应语音的目标误差不超过 120ms。

正脸或明显侧脸的说话人物必须执行口型同步；非说话人物保持闭口或自然微表情。多人镜头在提交口型任务前必须锁定 speaker。明显音节/嘴型错位、说话人错误或静音时持续张嘴均判失败，只重做该镜头的口型层，不重做已通过音频或全片。

`lip_sync_verified` 是独立验收标志，默认 `false`。只有官方 InfiniteTalk 模型栈在 RTX 3060 12GB 上完成真实稳定性和音画同步验收后，使用该栈并通过逐镜头检查的资产才可设为 `true`。使用旁白配合反应、越肩、文件、手部和细节镜头规避可见嘴部的作品可以完成叙事验收，但必须记录 `lip_sync_status=not_required_by_shot_design`、保持 `lip_sync_verified=false`，不得宣称完成真实口型同步。

### 9.3 Character Bible 与人物一致性

Character Bible 至少保存成年身份确认、角色 ID、脸部主参考、发型、妆容、体型、服装、配饰、色板、声线和禁改项。角色参考资产必须版本化、可锁定并允许人工选择主参考；刷新页面、创建修订版或重新生成不得丢失角色上下文。

每个镜头保存实际使用的角色参考图、seed、模型、LoRA、IP-Adapter、FaceID 等参数及版本。续镜默认继承上一镜通过验收的角色参考，而不只是复用文字提示词。系统抽取首/中/末帧执行身份一致性检测；脸型、发色、服装、配饰或年龄观感明显漂移时，仅将该镜头加入局部重试队列。

### 9.4 Scene Bible 与空间连续性

Scene Bible 保存场景 ID、时间、光向、主色温、家具/道具位置、天气、镜头轴线、角色站位和环境音底层。相邻镜头继承场景参考帧、光线、色调和关键物件；只有跨场景时允许改变，并记录 `transition_reason`。

连续动作默认使用上一镜末帧作为下一镜视觉条件，并保存动作起点/终点、视线方向和屏幕运动方向。自动检查色彩/亮度突变、背景结构漂移、服装变化、左右方向反转和环境音断裂；异常只进入对应镜头的局部重试队列。

### 9.5 小说及长文本

长文本按以下步骤逐层处理：

1. 文本导入与章节识别。
2. 故事设定、人物关系、时间线和地点抽取。
3. 分季和分集规划。
4. 每集分场与每场分镜。
5. 人物外观、服装、道具、地点、时间和情节状态的一致性检查。
6. 经人工确认后逐集进入短视频生产管线。

系统不一次性将整部小说送入模型，也不在未审阅时生成全部素材。每一层结果均可编辑和版本化，以控制上下文长度、GPU 成本和返工范围。

## 10. 素材库与简化时间线

每个素材记录以下来源信息：

- 原始文本及其版本引用
- 结构化提示词
- 模型与工作流版本
- 种子和受限生成参数
- 父素材和派生素材
- 创建人、项目和生成任务
- 文件摘要、格式、尺寸、时长和存储位置
- 角色/场景参考资产版本、实际 seed、模型、LoRA/IP-Adapter/FaceID 参数和质检分数
- 对齐结果、词级时间戳、SRT/ASS、原视频、口型修订版以及最终输出之间的素材血缘
- `media_generation_mode`、`source_image_id`、shot/cue 映射、恢复点和逐阶段 QA 状态

简化时间线支持镜头排序、入点/出点裁切、转场、音量、字幕调整、素材替换和重新合成。每个转场保存 `transition_type`、`duration_ms`、前后镜头句柄区间和音频衔接参数；按镜头内容选择动作匹配、视线匹配、构图匹配、J/L cut、短交叉淡化或硬切，不得机械使用同一转场。动作连续场景优先硬切或匹配切，默认转场保持短促以避免拖影。

配乐和环境音跨镜头连续，旁白/对白存在时自动压低音乐，对白切点不得截断呼吸或尾音。渲染前后检查首尾帧运动向量、主体位置、曝光与色温；闪帧、黑帧、主体变形或节奏停顿判为转场失败。第一版数据结构应可映射到未来多轨时间线，但不实现任意层叠、多机位或复杂关键帧动画。

口型模型、强制对齐模型、120ms 默认允许误差、角色一致性阈值、场景一致性阈值、允许转场类型/时长和局部重试次数全部属于租户级后台生产策略，复用 AI Resource 配置体系并按版本快照到任务，禁止散落在业务代码中。

## 11. 幂等、取消与恢复

生成请求在进入队列前必须持久化。幂等键由租户、用户、项目、操作类型、输入版本和客户端请求标识共同确定。浏览器重试或网络超时时，服务返回原任务，不重复提交 ComfyUI。

尚未执行的任务可以直接从平台队列取消。已经提交 ComfyUI 的任务进入“取消中”，平台尝试中断远端队列并持续跟踪直到确认停止。已经产生且校验有效的中间素材可以保留。

Worker 重启后读取数据库步骤状态，并查询 ComfyUI history 或队列，决定继续追踪、有限重试或转为“需人工处理”。对于无法确认 `POST /prompt` 是否成功的网络异常，禁止盲目再次提交。

系统只自动重试明确可恢复的连接故障和限流，不重试参数错误、工作流错误或提交结果不确定的请求。

错误分类至少区分：Cloudflare Access 401/403、Cloudflare `1033` Tunnel 无连接、ComfyUI 参数校验错误、GPU OOM、远端软超时、输出下载失败、输出校验失败和对象存储失败。`1033` 只表示 Tunnel 当时没有可用连接，不证明 GPU 任务失败；若任务已有 `prompt_id`，恢复顺序必须是先查 history、再查 queue，最后才决定继续等待、人工处理或有限重试。

## 12. 安全边界

- Cloudflare Access 凭据只存在于执行远端请求的服务端进程。
- 日志过滤认证请求头、Secret、完整用户原文和可能包含敏感值的远端响应。
- 前端只能选择白名单工作流和已声明参数，禁止上传任意 ComfyUI workflow。
- 服务端对提示词长度、上传大小、图片尺寸、视频帧数、采样步数、视频时长、批量数和项目配额设置硬上限。
- 内部版本同样记录内容安全判断、成年人确认和审计事件；涉及人物的成人内容必须明确为成年人，任何涉及未成年人的性化内容都必须拒绝进入生成队列。
- 按租户记录并限制并发、每日 GPU 秒数、最大视频长度和存储用量，即使内部版本暂不收费。
- 上传文件校验 MIME、扩展名、文件头、大小和摘要。
- 素材通过短时签名 URL 访问，不公开对象存储桶。
- 所有项目查询强制应用租户、组织角色和项目成员过滤。
- 错误响应提供可操作的信息和追踪 ID，但不暴露远端响应正文、内部路径或凭据。

公开 SaaS 阶段还需增加内容审核、滥用检测、支付安全、租户速率限制和数据保留策略；这些不是内部版本首个里程碑的阻塞项。

## 13. 测试策略

### 13.1 单元测试

覆盖权限、参数硬限制、幂等键、任务状态机、工作流参数注入、素材来源、参数快照、词级时间戳、字幕 120ms 误差、speaker 锁定、口型状态、`lip_sync_verified` 默认 false、两类 `media_generation_mode`、恢复点、人物/场景阈值和敏感字段过滤。

### 13.2 集成测试

使用模拟 Ollama、ComfyUI、Qwen3-TTS/对齐/口型 Provider、Redis、PostgreSQL 和对象存储，覆盖成功、超时、断线、取消、有限重试、重复请求、Worker 重启恢复和逐阶段局部重试。

故障测试必须单独覆盖 Cloudflare `1033`、Access 401/403、ComfyUI validation error、OOM、下载中断和对象存储失败，并证明已有 `prompt_id` 的任务不会因为这些网络错误而重复提交。

### 13.3 契约测试

验证适配器与交接文档中的 Ollama/ComfyUI API、ACE-Step/Stable Audio 两份已验证 API-format 工作流及 Qwen3-TTS Provider 契约兼容。测试固定验证 Windows 原生入口、队列为空、任务前后 `/free`、ACE 双 Qwen 编码器和 Access 401/403 中文映射。工作流升级必须产生新版本，不能原地改变已有任务的可重复性。

### 13.4 端到端测试

通过浏览器完成登录、输入文字、生成、刷新恢复进度、在线预览、下载、历史查询和权限隔离，并逐镜头查看生成方式、来源关键图、语音、字幕、口型、人物一致性、环境一致性、转场和人工复核状态，验证只重做失败阶段。界面必须把“关键图运动成片”“完整生成式视频”和“真实口型已验证/未验证”分别显示。

远程 GPU 测试区分日常最小参数冒烟与阶段正式验收。每个阶段只进行必要的完整真实生成，避免无意义消耗 GPU。测试输出和日志不得包含 Secret 或完整请求头。

### 13.5 CASE-0001 长文本成片参考基线

2026-10-19 的 CASE-0001 二次验证证明“长文压缩 → 24 段隔离 Qwen3-TTS 旁白 → 24 条字幕 → 15 张有效 Wan 2.2 关键图中选择 13 张 → 24 个关键图运动镜头 → ACE-Step 配乐 + Stable Audio 环境音 → 混音 → 成片”可形成 245.440 秒的 H.264 1280×720、16fps、AAC 48kHz 双声道文件。全片解码通过，综合响度 -15.9 LUFS，True Peak -1.5 dBFS；人工抽检 5、48、94、140、188、238 秒未观察到黑帧、字幕截断或明显画面破损。

该案例状态为 `passed_with_documented_limitations`：它验证的是 `generated_keyframe_motion`，不是 24 段 `full_generated_video`；真实口型未执行，`lip_sync_verified=false`。对白使用旁白配合反应、侧面、越肩、文件、手部和细节镜头规避可见错误口型。只有官方 InfiniteTalk 完整模型栈在 12GB GPU 上通过真实验收后，才能改变这一口型能力边界。

CASE-0001 还固定以下恢复与安全规则：已完成关键图不得在恢复后重复生成；Z-Image INT8 的 `int8_tensorwise` 已知不兼容流程不得自动回退；LoRA 模型补丁缓存异常只允许限定 PID 重启 Windows 原生 ComfyUI，重启后必须重新确认 `os=win32`、队列为空和模型清单，不得误切回 WSL 8188。合成案例必须展示虚构声明，不能包装成真实机构事实。

## 14. 可观测性与管理

管理页面显示：

- Ollama、ComfyUI、PostgreSQL、Redis、对象存储和 Worker 健康状态。
- 当前 GPU 租约持有任务、队列长度、阶段耗时和最近失败。
- 用户、项目和工作流维度的任务数、成功率、GPU 时长及存储量。
- 工作流模板版本和远程模型可用状态。
- 口型/对齐模型、允许误差、一致性阈值、转场策略和局部重试次数的当前版本。

指标、结构化日志和任务事件使用同一追踪 ID 关联。管理端只能查看脱敏错误摘要，原始诊断由受控运维日志保存。

## 15. 首个里程碑验收条件

以下条件全部满足才算完成：

1. Docker Compose 可从干净环境启动。
2. 内部用户可以登录并访问快速生成台。
3. 输入文字能够真实生成图片，刷新页面后仍可查看。
4. 输入文字能够完成首帧生成和图生视频，最终在线播放和下载平台存储的 MP4。
5. 同一幂等请求不会重复提交远端任务。
6. 两个同时到达的重型任务严格串行。
7. 远程故障、超时和 Worker 重启不会导致任务无故丢失或重复生成。
8. 普通用户无法提交任意工作流或突破服务端参数上限。
9. 代码、README、部署文档和测试证据保持同步。
10. 短故事的最终音频、词级对齐、字幕和口型使用同一权威时间轴，字幕误差目标不超过 120ms。
11. 人物与环境连续性、逐转场播放、ffprobe 和完整解码 Gate 全部通过；任一阶段失败可以只重做对应镜头/层。

## 16. 实施阶段

1. 平台基础、认证权限和本地基础设施。
2. 图片真实生成纵向切片。
3. 文字经首帧生成视频的真实纵向切片。
4. 任务历史、素材库和管理观测。
5. 短故事结构化分镜与 30 秒至 3 分钟短片。
6. 多镜头视觉圣经、逐镜头审核、FFmpeg/ffprobe 质量检查、简化时间线、声音轨道和成片合成。
7. 小说与长文本的分层拆解和批量镜头生产。
8. 公开注册、套餐、计费、内容审核和多租户运营。

每个阶段必须提供与范围匹配的测试证据，并在进入下一阶段前更新 README、路线图或既有交接文档。

## 17. 明确不在首个里程碑内的内容

- 专业多轨非线性编辑器。
- 外部用户公开注册、支付和套餐购买。
- 用户上传任意 ComfyUI workflow。
- 多 GPU 或跨节点调度。
- 自动批量生成整部长篇作品。
- 未经人工审阅就持续消耗 GPU 的全自动长篇流水线。
- 语音克隆、数字人以及未经授权参考音频的声音复刻。

这些边界用于保证第一项交付是可运行、可恢复、可管理的真实生成链路，而不是功能很多但无法完成端到端任务的演示页面。
